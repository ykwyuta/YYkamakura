# 承久の乱までの史実再現検証（初回）

このページは改善前 `700fed4` の基準記録を保存したもの。共同出兵・遠征AI・戦役の時間配分を変更した[第1回改善と再検証](improvement-1/README.md)も参照。

**判定：現状は、史実に近い勢力の盛衰を再現できていない。** 年表と人物の退場はおおむね機能するが、平家・奥州藤原氏の没落、鎌倉と北条氏の主導権、承久の乱の帰結が成立しない。

対象は `700fed4` のゲーム挙動。ルール・AI・年表の効果・地形・時間を変えず、監査用テストだけを追加して観測した。乱数 `1, 42, 2026, 12345, 8675309` の5通りで、1179年1月から1221年7月まで全勢力をAI操作した。戦闘を飛ばす年代送りは使っていない。各試行の15時点で40勢力と63英雄を記録し、全拠点の攻略履歴と、全28件のイベントの実際の主体を採取した。

5試行とも最後まで進み、46拠点の保存と28件のイベント処理は確認できた。これは史実への近さの合格を意味しない。

## 主要な結果

| 史実を基準にした判定 | 実測 |
|---|---|
| 1183年の平家都落ち | 1183年8月でも六波羅は全試行で平家領。0/5 |
| 1184年の義仲勢の敗退 | 全試行で独立勢力のまま。実際の併合は1186.7〜1192.8年 |
| 1185年の平家滅亡 | 0/5。1221年になっても全試行で2〜5拠点を領有 |
| 1189年の奥州藤原氏滅亡 | 0/5。1221年になっても全試行で3〜6拠点を領有 |
| 比企・畠山の政変 | 翌月の時点ではいずれも0/5。比企は1205.6〜1215.2年、畠山は1207.1〜1215.7年に別の勢力も含めて併合 |
| 和田合戦 | 1213年6月時点では0/5。ただし史実の時期から±1年以内の和田氏の消滅は4/5。北条氏が併合するのは1/5 |
| 1221年の幕府方の勝利 | 0/5。全試行で平安京を朝廷が保持したままゲーム終了 |

表の都落ち・政変・京都攻略はゲーム内の代理指標である。特に「朝廷を併合する」はゲーム上の政治権力の移動を表し、史実で朝廷制度が消滅したという意味ではない。対象家の男系・系統すべての断絶を検証しているわけでもない。

**機能した部分**：1180年の頼朝と北条・千葉・三浦の休戦、1187年の義経の奥州所属、1199年の頼朝退場、1219年の実朝退場、承久の乱前の朝廷保護、1221年5月の朝廷対北条の開戦は、いずれも5/5で確認した。

1180年の鎌倉領有も5/5だが、開始時から源氏領なので、頼朝の進出を再現できた証拠にはならない。日付で退場する英雄が正しく消えても、残る兵・施設・勢力の歴史的な敗北まで再現したことにはならない。

全判定・最終拠点数・併合年・実際の併合者は[実測表](measurements.md)、機械可読データは[summary.json](summary.json)、生データは[raw](raw/)を参照。

## 原因

1. **史実イベントの効果が主として休戦・宣戦・人物退場にとどまる。** 「都落ち」「壇ノ浦」「奥州合戦」という記録が出ても、戦後の支配や勢力整理が起きるとは限らない。[年表の効果](../../src/world/history.rs)は領有を基本的に実際の攻略に委ねている。広常誅殺の上総併合など、一部だけが直接の併合効果を持つ。
2. **同盟が共同戦線になっていない。** 休戦は相互攻撃を止めるだけで、頼朝の敵に御家人が共同出兵する主従・動員の仕組みがない。1180年11月の実測でも、北条・千葉・三浦のいずれも、5試行すべてで平家と交戦していなかった。和田合戦における三浦氏の離反なども、歴史的な立場の切り替えとして年表に定義されていない。
3. **汎用AIが歴史的な作戦目標を持たない。** [外交・軍事AI](../../src/ai.rs)は、1191年以降の自由宣戦では近くの弱い勢力を狙い、交戦中は近い敵とその城邑を選ぶ。東国勢力をまとめて西国へ向かう、平家の退却経路を追う、奥州へ兵を集中する、といった方針がない。
4. **承久の乱の進軍に対して時間が短い。** 開戦から終了まで約8秒。実際の初期マップで鎌倉〜平安京は直線約166.7マス、騎馬武者は3.2マス/秒。無抵抗・地形無視でも約52.1秒、ゲーム内約13か月かかる。5月に鎌倉から発つ軍では終了に間に合わない。これは前進配置された部隊の可能性まで否定するものではない。[移動計測](raw/travel.json)
5. **史実の主体が継承先へ置換される。** 乱数2026では源氏が1213年末に佐竹氏へ併合され、1219年の「実朝暗殺」の記録主体は佐竹氏となった。イベント数が28件揃っていても、歴史的な政治構造が保たれているとは限らない。
6. **初期領有に後年の状況の先取りがある。** 1179年開始の時点から源氏が鎌倉を領有する。既存の拠点を置いておくことと、その時期の所有者を正しく設定することは別の検証項目であり、現在の配置では「1180年に鎌倉を獲得した」という過程を評価できない。

## 改善の優先順位

ゲームの自由度を保ちながら史実へ近づけるには、個々の兵の強さの調整だけでは不十分。

1. 初期領有を1179年の状況に近づけ、幕府・御家人・平家方・朝廷方の主従関係と、対外戦への共同動員を導入する。各家の固有英雄と固定拠点は維持する。
2. 東国結集、西国追討、奥州追討、承久の乱という段階ごとのAI目標・集合地点・補給・輸送を設ける。
3. 月単位の合戦を実行できる時間配分と進軍速度を設計する。特に1221年は、既存拠点への事前集結や戦役中の時間の流れを含めて調整する。
4. 内政政変と野戦による勢力整理を分ける。比企・畠山・和田の事件は、単なる遠隔拠点の包囲戦にならないようにする。
5. 日付、当事者、勝敗、攻略した既存拠点、併合後の所属を個別に評価し、同じ乱数セットと追加の乱数で再測定する。史実の戦果を条件付きイベントとして補うかは、その時点でゲーム方針として決める。

今回の変更は検証と証拠の保存に限定し、これらの改善によって結果を作り替えることはしていない。

## 再現する

```powershell
cargo test --release --locked --lib historical_campaign_audit -- --ignored --nocapture
cargo test --release --locked --lib historical_travel_audit -- --ignored --nocapture
python tools/summarize_history_audit.py
```

通常のテストには重い5試行の監査を含めない。ゲームを更新して測り直す際は、変更内容とコミットを記録してから実行する。乱数を変更する場合は `KAMAKURA_AUDIT_SEEDS` と集計側の `--seeds` を同じ値にする。

5試行は探索的な挙動確認であり、全乱数における再現率を推定したものではない。プレイヤーの介入や勢力・初期条件の変更を含む評価も今回の範囲外とした。
